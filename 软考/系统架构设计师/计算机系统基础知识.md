## 二、计算机硬件 ⭑

### 2.1 冯·诺依曼 5 大组成部分

**控制器、运算器、存储器、输入设备、输出设备**。

- **运算器和控制器**合称**处理器（CPU）的核心部件**。
- 处理器指令集按复杂程度分：**CISC（复杂指令集）** 与 **RISC（精简指令集）**。
- 专用处理器：
  - **GPU**：数百至数千内核，经优化后**可并行运行大量计算**，广泛用于深度学习 / 机器学习。
  - **DSP**（数字信号处理器）：专用于**实时数字信号处理**，用**饱和算法**处理溢出，用**乘累加**提高矩阵运算效率，并为**傅里叶变换设计专用指令**。
  - **FPGA**（现场可编程逻辑门阵列）。

### 2.2 存储器分层（4 层）⭑

| 层次 | 结构 | 容量 | 特点 |
| ---- | ---- | ---- | ---- |
| **① 片上缓存** | SRAM | 16kB～512kB | 集成在处理器核心**内部**，实现数据快速读取；可能划分为一级或二级 |
| **② 片外缓存** | SRAM | 256kB～4MB | 在处理器核心**外**，需经交换互联开关访问；按层级称 L2/L3 Cache 或**平台 Cache** |
| **③ 主存（内存）** | DRAM | 数百 MB～数十 GB | 以**独立部件/芯片**存在，通过总线与处理器连接；**依赖不断充电维持数据** |
| **④ 外存** | 磁带/磁盘/光盘/Flash | 大 | 访问速度慢、容量大，**断电后仍能保持数据** |

> 存储介质按硬件结构分：SRAM、DRAM、NVRAM、Flash、EPROM、Disk 等。

### 2.3 总线与接口

- **总线**：计算机部件间**遵循某一特定协议实现数据交换**的形式。
- 按位置分：**内总线**（片内总线、系统总线）和**外总线**。
  - **系统总线** = CPU + 主存 + I/O 接口的总线（狭义 = CPU 与主存、通信桥连接的总线；广义还含系统总线）。
  - **外总线** = 计算机板与外设之间、或计算机系统之间互联的总线，也叫**通信总线**。
- 总线性能指标：**带宽、宽度、工作频率**；性能指标是**吞吐量、总线 QoS**。
- 总线分类：**并行总线**（PCI、PCIe、ATA、IDE）与**串行总线**（USB、SATA、CAN、RS-232、RS-485、RapidIO、以太网）。
- **接口**是两台计算机不同功能层之间的通信规则；常见类型：显示、音频输入输出、网络、PS/2、USB、SATA、LPT、RS-232 等。
- **一种总线可能存在多种接口**。

## 三、计算机软件（操作系统基础）⭑

### 3.1 软件分类

| 类型 | 说明 |
| ---- | ---- |
| **系统软件** | 为整个计算机系统配置的、**不特定对应特定应用**的软件，如**操作系统**、语言处理程序、数据库管理系统等；负责对计算机硬件和软件资源进行管理控制 |
| **应用软件** | 为特定应用需求开发的软件，如图形图像处理、财务、游戏等 |

- **操作系统是计算机资源的管理者**，包含对系统软硬件资源实施管理的一组程序。
- 主要作用：通过 **CPU 管理、存储管理、设备管理、文件管理**，对各种资源合理分配，改善资源利用率，提高效率。
- 操作系统是**大型、复杂的软件产品**，由**内核 + 许多附加软件**组成（图形用户界面、应用程序、实用程序、软件开发工具等）。

### 3.2 操作系统的三大作用 ⭑

1. **管理计算机中运行的程序和分配各种软硬件资源**；
2. **为用户提供友好的人机界面**；
3. **为应用程序的开发和运行提供一个高效率的平台**。

### 3.3 操作系统的四大特征

**并发性、共享性、虚拟性、不确定性**（口诀"并共虚不"）。

### 3.4 操作系统的分类（7 种）

| 类型 | 关键特点 |
| ---- | -------- |
| **批处理操作系统** | 单道批 / 多道批（**多道：宏观上并行运行、微观上串行运行**） |
| **分时操作系统** | 多路性、独立性、交互性、及时性 |
| **实时操作系统** | 分为**实时控制系统**和**实时信息处理系统** |
| **网络操作系统** | 硬件独立性和多用户支持 |
| **分布式操作系统** | 保持网络系统全部功能，同时有**透明性、可靠性、高性能** |
| **微型机操作系统** | Windows、Mac OS、Linux 等 |
| **嵌入式操作系统** | **微型化、可定制、实时性、可靠性、易移植性** |

## 四、进程管理 ⭑

### 4.1 进程的组成

**进程控制块 PCB**（**唯一标志**）、**程序**（描述进程要做什么）、**数据**（存放进程执行时所需数据）。

### 4.2 进程三态及转换 ⭑

- 状态：**运行、就绪、阻塞**。
- 转换条件：

| 转换 | 触发条件 |
| ---- | -------- |
| 就绪 → 运行 | **被调度**（分配处理器） |
| 运行 → 就绪 | **时间片到**（或被更高优先级抢占） |
| 运行 → 阻塞 | **等待某事件**（请求 I/O、P 操作失败等） |
| 阻塞 → 就绪 | **等待的事件发生** |

> ⚠️ 高频考点：**"运行 → 就绪"的原因是"时间片用完 / 主动让出 CPU"**；**阻塞不能直接→运行**，必须先回到就绪（因为处理器是抢占式分配的）。

### 4.3 P 操作与 V 操作 ⭑

| 操作 | 含义 | 逻辑 |
| ---- | ---- | ---- |
| **P 操作** | **申请资源**，`S = S − 1` | 若 `S ≥ 0`，继续执行；若 `S < 0`，进程变**阻塞**并插入**阻塞队列** |
| **V 操作** | **释放资源**，`S = S + 1` | 若 `S > 0`，继续执行；若 `S ≤ 0`，从阻塞队列**唤醒一个进程**并插入**就绪队列**，然后继续 |

> ⚠️ 信号量 `S` 的取值含义（2025-11 真题）：**`S < 0` 时，|S| 表示正在等待的进程数**。
> - 互斥信号量 `mutex` 初值为 **1**；`mutex = 0` 表示有 1 个进程在临界区、无人等待；
> - **`mutex = −1` 表示"一个进程进入临界区，另一个进程在等待"**。

### 4.4 死锁 ⭑

**死锁**：一个进程在等待**永远不可能发生的事件**；多进程同时处于死锁状态即系统死锁。

**死锁产生的 4 个必要条件**（缺一不可）：

1. **互斥**（资源互斥）
2. **占有并等待**（每个进程占有资源并等待其他资源）
3. **不可剥夺**（系统不能剥夺进程资源）
4. **循环等待**（进程资源图是一个环路）

**解决死锁的 4 种策略**：

| 策略 | 做法 |
| ---- | ---- |
| **死锁预防** | 采用某策略**限制并发进程对资源的请求**，破坏 4 条件之一，使系统任何时刻都不满足死锁条件 |
| **死锁避免** | **银行家算法**：提前计算出一条不会死锁的资源分配方案（相当于"借贷"时考虑对方还得起才借） |
| **死锁检测** | 允许死锁产生，系统定时运行**检测程序**，发现死锁再设法解除 |
| **死锁解除** | 检测到后**强制剥夺资源、撤销进程**等 |

**死锁资源计算公式** ⭑（必背）：
> 系统有 n 个进程，每个进程需要 R 个资源，则**发生死锁的最大资源数 = n(R−1)**，**不发生死锁的最小资源数 = n(R−1) + 1**。

**典型题**：5 个进程各需 2 个资源 → 不发生死锁最少需 `5×(2−1)+1 = 6` 个。

### 4.5 线程 vs 进程 ⭑

| 维度 | 进程 | 线程 |
| ---- | ---- | ---- |
| 传统两个属性 | **可拥有资源的独立单位**；**可独立调度和分配的基本单位** | 把"调度和分配"这个属性**分离**出来，线程是**调度和分配的基本单位** |
| 资源 | 作为**独立分配资源**的单位，拥有全部资源 | **基本上不拥有资源**，只拥有运行中必不可少的资源（程序计数器、一组寄存器和栈） |
| 共享 | — | 与**同属一个进程**的其他线程**共享进程所拥有的全部资源**（公共数据、全局变量、代码、文件）；**不能共享线程独有的资源**（如栈指针等标识数据） |

> **引入线程的原因**：进程在创建、撤销和切换中需付出较大时空开销，故系统中进程数目不宜过多、切换频率不宜太高，这限制了并发度提高。改用线程后，**用户可通过创建线程来完成任务，以减少程序并发执行时的时空开销**。

## 五、存储管理 ⭑

### 5.1 页式存储与地址变换

- **逻辑地址**分为**页号**和**页内地址**；**页内地址就是物理偏移地址**。
- **页号与物理块号并非按序对应**，需查**页表**才能得页号对应的物理块号，再用物理块号 + 偏移地址得出真正运行时的物理地址。
- **优点**：利用率高、碎片小、分配及管理简单。
- **缺点**：增加了系统开销，**可能产生抖动现象**。
- **地址变换过程**：页表地址寄存器 + 页号 → 查页表得物理块号；页表长度寄存器 L 用于判断"若 L ≤ 页号，则地址越界"。

### 5.2 页面置换算法 ⭑

| 算法 | 原理 | 特点 |
| ---- | ---- | ---- |
| **最优算法 OPT** | 理论上的算法，**无法实现**；用于在进程执行完后进行最佳效率计算，用来让其他算法比较差距。原理是**置换未来最长时间内不被访问的页面** | 只是理想基准 |
| **先进先出 FIFO** | 先调入内存的页先被置换淘汰 | **会抖动**，且**分配的页数越多、缺页率可能越高**（效率低） |
| **最近最少使用 LRU** | 在最近的过去，置换**过去最少使用**的页面；根据局部性原理 | 效率高、**不会抖动**、使用大计数器；**但没有 LFU** |

- **淘汰原则**：优先淘汰**最近未访问**的，而后淘汰**最近未被修改**的页面。
- **快表** ⭑：
  - 是一块**小容量的相联存储器**，由**快速缓存器**组成；
  - **按内容访问**、速度快，可从硬件上保证**按内容并行查找**；
  - 一般用于存放**当前访问最频繁的少数活动页面的页号**；
  - **快表**将页表存于 Cache 中，**慢表**将页表存于内存中。**慢表需要访问两次内存才能取出页，快表只访问一次 Cache 和一次内存**，因此更快。

## 六、文件管理 ⭑

### 6.1 文件与文件说明

- **文件**是具有**符号名的、在逻辑上具有完整意义的一组相关信息项的集合**。
- **信息项**是构成文件内容的基本单位（可以是字符，也可以是记录；等长或不等长）。
- **文件说明**是操作系统为管理文件所用的信息，包括**文件名、文件内部标识、文件类型、文件存储地址、文件长度、访问权限、建立时间和访问时间**等。

### 6.2 文件的物理结构（3 种）⭑

**文件的逻辑结构**分两大类：**有结构的记录式文件**、**无结构的流式文件**。

**文件的物理结构**指文件在物理存储设备上的存放方法：

| 结构 | 说明 |
| ---- | ---- |
| **① 连续结构（顺序结构）** | 将逻辑上连续的文件信息（如记录）**依次存放在连续编号的物理块**上 |
| **② 链接结构（串联结构）** | 将逻辑上连续的文件信息存放在**不连续**的物理块上，每个物理块设**一个指针**指向下一个物理块 |
| **③ 索引结构** | 将逻辑上连续的文件信息存放在**不连续**的物理块上，系统为每个文件**建立一张索引表**；索引表记录文件信息所在的逻辑块号对应的物理块号，并将索引表起始地址放在文件对应的目录项中 |
| **④ 多个物理块索引表** | 索引表在文件创建时由系统自动建立，**与文件一起存放在同一文件卷上**；根据文件大小不同，索引表占用物理块的个数不等 |

### 6.3 文件的存取方法与存储空间管理 ⭑

- **存取方法**：**顺序存取**（按文件中的信息**按顺序依次读/写**）和**随机存取**（按**任意次序随机读/写**）。
- **存储空间管理（位示图 Bitmap）**：
  - 在外存上建立一张位示图，记录文件存储器的使用情况；
  - **每一位对应文件存储器上的一个物理块，取值 0 和 1 分别表示空闲和占用**。
  - **计算**：总块数 = 柱面数 × 盘面数 × 每面扇区数；**需位数 = 总块数**；**需字数 = 总块数 ÷ 字长**；**需字节数 = 字数 × (字长÷8)**。

> 常见误答：把"位示图大小"直接当成磁盘块数。**必须再除以字长**（题目问"字"则除字长；问"字节"再乘每字字节数）。
> 例：10 柱面 × 10 盘面 × 16 扇区 = 1600 块 → 1600 位 → 字长 16 位 → **100 字**（= **200 字节**）。

### 6.4 目录与路径

- **绝对路径**：**从根目录开始**，沿每一级子目录逐步向下到达指定文件的整个通路上所有子目录名组成的字符串。
- 目录结构演进：**单级目录**（全系统一个目录）→ **两级目录**（主文件目录 MFD + 用户文件目录 UFD）→ **树形目录**（现代标准）。

## 七、嵌入式系统及软件 ⭑

### 7.1 定义与组成

**嵌入式系统**以应用为中心、以计算机技术为基础，将**可配置与可裁减**的软硬件**集成于一体**的**专用计算机系统**，需满足对功能、可靠性、成本、体积和功耗的严格要求。

组成（5 部分）：

| 组成 | 说明 |
| ---- | ---- |
| **① 嵌入式处理器** | 工作环境恶劣，需抗恶劣环境（高低温、寒冷、电磁、加速度）；按环境分**民用、工业、军用三个档次** |
| **② 相关支撑硬件** | 除处理器外构成系统的其他硬件：存储器、定时器、总线、I/O 接口及相关专用硬件 |
| **③ 嵌入式操作系统** | 运行在嵌入式系统中的基础软件，管理计算机资源和应用软件；与通用 OS 不同，应具备**实时性、可剪裁性和安全性** |
| **④ 支撑软件** | 为应用软件开发与运行提供公共服务、软件开发、调试能力的软件；通常运行在操作系统之上，以**库**的方式被应用软件引用 |
| **⑤ 应用软件** | 为完成某一特定目标而开发的软件 |

### 7.2 嵌入式系统的 8 条特性 ⭑

1. **专用性强**（面向特定应用需求，可把通用 CPU 中许多由板卡完成的任务集成到芯片内部 → 小型化）
2. **技术融合**（技术密集、资金密集、高度分散、不断创新的知识集成系统）
3. **软硬一体软件为主**（软件是主体，有 IP 核；软硬件都可高效设计、量体裁衣）
4. **比通用计算机资源少**（只完成少数几个任务，考虑到经济性，成本低、结构更简单）
5. **程序代码固化在非易失存储器中**（为提高执行速度和可靠性，一般固化在存储器芯片或单片机本身中，而非磁盘）
6. **需专门开发工具和环境**（本身不具备开发能力，需一套开发工具和环境）
7. **体积小、价格低、工艺先进、性能价格比高、系统配置要求低、实时性强**
8. **对安全性和可靠性的要求高**

### 7.3 嵌入式系统的分类与 5 层结构

**分类**：按用途分**嵌入式实时系统**（又分**强实时 / 弱实时**）和**嵌入式非实时系统**；按安全性分**安全攸关系统**和**非安全攸关系统**。

**5 层结构**（自底向上）：

| 层 | 说明 |
| -- | ---- |
| **① 硬件层** | 为嵌入式系统运行提供支持的硬件环境，核心是微处理器、存储器（ROM/SDRAM/Flash 等）、I/O 接口（A/D、D/A、I/O 等）和通用设备以及总线、电源、时钟等 |
| **② 抽象层** | 主要在硬件层和软件层之间**对硬件进行抽象**，为上层应用提供虚拟的硬件资源；板级支持包 **BSP** 是一种硬件驱动软件，面向硬件芯片或电路进行驱动 |
| **③ 操作系统层** | 主要由嵌入式操作系统、文件系统、图形用户接口、网络系统和通用组件等**可配置模块**组成 |
| **④ 中间件层** | 一般位于操作系统之上，管理计算机网络和网络通信；是**连接两个独立应用的桥梁** |
| **⑤ 应用层** | 嵌入式系统的具体应用 |

### 7.4 DO-178B / DO-178C（航空软件标准）⭑

**DO-178B 的目的**：为制造机载系统和设备的机载软件提供指导，使其能满足在符合适航要求的安全性水平下完成预期功能。三方面指导：

- **a. 软件生命周期过程的目标**
- **b. 为满足上述目标要进行的活动**
- **c. 证明上述目标已经达到的证据**

**三个基本要求**：**目标、过程、数据**。

| 层级 | 内容 |
| ---- | ---- |
| **（1）目标** | DO-178B 规定软件整个生命周期需要达到的 **66 个目标**；按安全等级分为 **A～E 五级**，不同安全等级的软件需达到的目标要求不同 |
| **（2）过程** | 分「**软件计划过程**」「**软件开发过程**」「**软件综合过程**」，后两者又各自细分 4 个子过程 |
| **（3）数据** | 把生命周期中产生的文档、代码、报表、记录等**所有产品统称软件生命周期数据** |

**软件开发过程的 4 个子过程**（自顶向下、由粗及细、从无到有）：

**① 软件需求过程**（输出开发高层需求）→ **② 软件设计过程**（对高层需求细化，开发软件体系结构和低层需求）→ **③ 软件编码过程**（对软件体系结构和低层需求编写源代码）→ **④ 集成过程**（对源代码和目标码编译、链接并加载到目标机，形成机载系统或设备的所有活动）。

**软件综合过程的 4 个子过程**：

| 子过程 | 说明 |
| ------ | ---- |
| **软件验证过程** | 对软件产品和验证结果进行技术评估，保证正确性、合理性、完整性、一致性、无歧义性 |
| **软件配置管理过程** | 对数据进行配置标识、基线建立、更改控制、软件产品归档等 |
| **软件质量保证过程** | 包含对数据和过程进行审计的所有活动，保证目标得以实现、缺陷得以检测 |
| **审定联络过程** | 软件研制单位与合格审查机构之间建立交流和沟通的所有活动 |

> ⚠️ **安全等级对应关系**（必背）：**Catastrophic（灾难性）→ Level A**；Hazardous/Severe → B；Major → C；Minor → D；No Effect → E。
> **DO-178C 与 CMMI 的区别**：DO-178C 专门针对航空安全、**目标更具体、更清晰**；CMMI 是通用过程评估模型（侧重组织过程能力）。
