# C++ 版本演进总结

> 从 1998 年首个 ISO 标准到 2023 年的 C++23，C++ 已走过七次标准迭代。理解版本演进，是看懂现代 C++ 代码、跟上生态趋势的钥匙。

## 一、版本总览

C++ 标准采用「大版本打基础、小版本做修补」的节奏，但 2011 年后基本维持三年一迭代：

| 版本 | 发布年份 | 定位 | 里程碑？ |
| ---- | -------- | ---- | :------: |
| C++98 | 1998 | 首个 ISO 标准，语言/标准库定型 | 是（奠基） |
| C++03 | 2003 | 缺陷修复小修订 | 否 |
| C++11 | 2011 | **现代 C++ 起点**，全面革新 | 是 |
| C++14 | 2014 | 完善 C++11，向后兼容 | 否 |
| C++17 | 2017 | 实用特性大集合 | 是 |
| C++20 | 2020 | 概念/协程/模块，革命性更新 | 是 |
| C++23 | 2023 | 修补 + 新容器（最新版） | 部分 |
| C++26 | 预计 2026 | 反射、契约、模式匹配 | 规划中 |

## 二、C++98 —— 语言与标准库的定型（1998）

### 背景
C++ 诞生于 1983 年，经历了十余年「各编译器各自为政」的混乱期。1998 年首个 ISO 标准发布，终结了方言分裂，让语言实现与代码可移植性有了统一依据。

### 核心内容
- **标准模板库（STL）**：`vector`、`list`、`map` 等容器，`sort`、`find` 等算法，迭代器抽象——「泛型编程」从此成为 C++ 的标志。
- **模板（Template）**：模板函数与模板类，为泛型与元编程打下根基。
- **异常处理**：`try/catch/throw` 进入标准。
- **标准库设施**：`string`、`iostream`、`new/delete`、RTTI（`dynamic_cast`、`typeid`）。

### 局限
没有 `auto`、lambda、智能指针；内存全靠手动 `new/delete`，写起来繁琐且易错。

```cpp
// C++98 风格：手动管理内存 + 冗长类型声明
std::vector<int>* v = new std::vector<int>();
for (std::vector<int>::iterator it = v->begin(); it != v->end(); ++it) {
    std::cout << *it << " ";
}
delete v;
```

## 三、C++03 —— 缺陷修复小修订（2003）

- 仅修复 C++98 发布后发现的缺陷（Defect Reports），**未增加实质新特性**。
- 明确了「值初始化」等个别语言细节。
- 是 C++98 的勘误版，两者在实践上可视为同一标准（常写作 C++98/03）。
- 由于长期没有大版本更新，业界一度传言"C++ 已死"——直到 C++11 打破僵局。

## 四、C++11 —— 现代 C++ 的起点（2011）⭐

> 时隔 13 年的大版本，几乎重写了语言的使用方式，**是现代 C++ 的分水岭**。2011 年之后写的 C++ 与之前「几乎是两门语言」。

### 核心特性

**1. 类型推导与空指针**
- `auto`：让编译器推导变量类型，简化冗长声明。
- `decltype`：获取表达式类型。
- `nullptr`：类型安全的空指针，取代 `NULL`（本质是 0，存在重载歧义）。

**2. 移动语义（右值引用）**
- `T&&` 右值引用区分「可移动的临时值」，配合**移动构造函数/移动赋值**，把"深拷贝开销"降为"指针交接"。
- 性能质变：`vector<string>` 返回/扩容不再频繁深拷贝。
- `std::move` 把左值"标记"为右值以触发移动。

**3. Lambda 表达式**
- 就地定义匿名函数，配合 STL 算法（`std::for_each`、`std::sort` 自定义比较）非常顺手。

**4. 智能指针（RAII 内存管理）**
- `std::unique_ptr`：独占所有权，零开销。
- `std::shared_ptr`：共享所有权，引用计数。
- `std::weak_ptr`：弱引用，打破 shared_ptr 循环引用。
- 从此基本告别裸 `new/delete`。

**5. 范围 for 循环**
```cpp
for (const auto& x : vec) { /* ... */ }
```

**6. 其他重要特性**
- 默认参数模板、变参模板（`template<typename... Args>`）。
- `constexpr`：编译期求值函数。
- 统一初始化 `{}` 与初始化列表 `std::initializer_list`。
- 委托构造、`override`/`final` 关键字。
- 标准库线程：`std::thread`、`std::mutex`、`std::atomic`。
- `std::unordered_map/set`（哈希表）加入标准库。
- `std::function`（可调用对象包装）、`std::bind`。

```cpp
// C++11 风格：auto + 智能指针 + lambda
std::vector<std::string> names = {"C++98", "C++11", "C++17"};
std::sort(names.begin(), names.end(),
          [](const std::string& a, const std::string& b) {  // lambda
              return a.size() < b.size();
          });
auto p = std::make_unique<int>(42);  // 智能指针
for (const auto& n : names)          // 范围 for + auto
    std::cout << n << "\n";
```

## 五、C++14 —— 对 C++11 的完善（2014）

- **泛型 lambda**：lambda 参数可用 `auto`，自动推导参数类型。
- **返回类型推导**：普通函数可用 `auto` 推导返回值（不用尾置返回类型）。
- `constexpr` 放宽：支持更多语句（循环、分支）。
- **二进制字面量** `0b1010`、**数字分隔符** `1'000'000`，可读性提升。
- `std::make_unique` 补进标准库。
- 定位：**零破坏的平滑升级**，C++11 代码可直接编译到 C++14。

## 六、C++17 —— 实用主义大版本（2017）⭐

> 与 C++11 的「革命」不同，C++17 更像「生产力工具箱」：把日常开发中最常见的痛点一次性补齐，**是当前工业界应用最广的标准之一**。

### 核心特性

**1. 新标准库类型**
- `std::optional<T>`：可能为空的值（替代返回值 + bool 标志的陋习）。
- `std::variant<A,B,C>`：类型安全联合体（替代裸 `union`）。
- `std::any`：可装任意类型的单值容器。
- `std::string_view`：字符串的只读"视图"，零拷贝传参。
- `std::filesystem`：跨平台文件/目录操作正式入标准库。

**2. 结构化绑定**
```cpp
auto [key, value] = map.insert({k, v});       // 拆解 pair
auto [iter, inserted] = mymap.emplace(1, "a");
```

**3. 编译期分支 `if constexpr`**
- 模板中按类型在**编译期**裁掉无效分支，替代大量 `enable_if` 黑魔法。

**4. 其他**
- `if/switch` 中直接写初始化语句：`if (auto it = m.find(k); it != m.end())`。
- 内联变量（`inline` 修饰全局变量，解决头文件多定义问题）。
- 折叠表达式（变参包直接展开运算）。
- `std::clamp`、`std::gcd/lcm`、`std::byte`。
- 并行 STL：`std::sort(std::execution::par, ...)`。
- 保证**拷贝省略**（C++17 起按值返回临时对象不再调用拷贝构造）。

```cpp
// C++17：optional + 结构化绑定 + string_view
std::optional<int> parse_int(std::string_view sv) {
    // ... 解析失败返回 std::nullopt
    return value;
}
if (auto r = parse_int("42"); r) {
    std::cout << *r << '\n';
}
auto [k, v] = std::pair<int, int>{1, 2};  // 结构化绑定
```

## 七、C++20 —— 革命性更新（2020）⭐

> 被誉为"C++11 之后最大的一次升级"，四个重磅特性（概念/范围/协程/模块）直指 C++ 多年痛点，官方定位为「下一个时代的 C++」。

### 核心特性

**1. Concepts（概念）—— 约束模板**
- 给模板参数加语义约束，错误信息从几百行"天书"变成清晰提示。
- 编译器只对满足约束的类型实例化，还能实现**函数重载按约束择优**。

```cpp
template <typename T>
concept Number = std::is_arithmetic_v<T>;

template <Number T>          // 只有算术类型能通过编译
T add(T a, T b) { return a + b; }
```

**2. Ranges（范围库）—— 组合式算法**
- 让算法可**链式管道组合**：`v | std::views::filter(...) | std::views::transform(...)`。
- 惰性求值 + 视图，代码接近声明式风格。

**3. 协程（Coroutines）—— 异步新范式**
- `co_await` / `co_yield` / `co_return` 原生关键字。
- 让异步代码写成同步的"顺滑"形态，网络库、生成器、UI 事件流受益巨大。
- 注意：协程是**框架设施**，标准库只提供底层机制，需要库封装（如 cppcoro）。

**4. Modules（模块）—— 告别头文件**
- 取代 `#include` 文本包含机制：编译一次、隔离性好、构建速度大幅提升。
- `export module foo;` / `import foo;`。
- 现状：编译器已支持，但生态工具链（构建系统）仍在磨合。

**5. 其他重要特性**
- **三向比较 `<=>`**：一次定义 `operator<=>`，编译器自动生成全部比较运算符（`<` `>` `<=` `>=`）。
- `consteval`（强制编译期函数）、`constinit`。
- `std::format`：printf 的性能 + Python format 的语法。
- `std::span`：连续内存的视图，安全替代裸指针+长度。
- `std::jthread`：析构自动 join 的线程。
- `std::barrier`/`std::latch`、`std::atomic<shared_ptr>`、`std::semaphore`。
- 位域 `using enum`、lambda 模板参数、`explicit(bool)`、`std::erase_if`。

```cpp
// C++20：format + spaceship + range
std::cout << std::format("{:>8} | {}", "key", "value") << '\n';

struct Point { int x, y; auto operator<=>(const Point&) const = default; };
Point a{1, 2}, b{1, 3};
if (a < b) { /* 自动生成的比较 */ }

auto r = std::vector{1, 2, 3, 4, 5}
       | std::views::filter([](int n) { return n % 2 == 0; })
       | std::views::transform([](int n) { return n * n; });
```

## 八、C++23 —— 最新正式标准（2023）

> 定位为「C++20 的完善 + 补短板」，没有划时代特性，但实用价值高，编译器支持已日趋完整。

### 核心特性

- **`std::expected<T, E>`**：函数式错误处理，返回"值或错误"二选一（对标 Rust 的 `Result`），比异常更轻量、比错误码更安全。
- **`std::flat_map` / `std::flat_set`**：基于排序数组的容器，内存紧凑、缓存友好，小数据量读写常快于红黑树。
- **`std::mdspan`**：多维数组视图，数值计算（科学计算/图像）的利器。
- **多维下标运算符 `a[i, j, k]`**：`operator[]` 可接收多个参数。
- **deducing this**：显式对象参数，极大简化 CRTP、`const` 重载、递归 lambda 的写法。
- `if consteval`、lambda 捕获 `*this`、`std::print`、`std::move_only_function`。
- 改进：`std::string::contains()`、`std::optional` 支持范围操作、`std::ranges::to`。

```cpp
// C++23：expected 风格错误处理
std::expected<int, std::string> divide(int a, int b) {
    if (b == 0) return std::unexpected("div by zero");
    return a / b;
}
if (auto r = divide(10, 2); r) {
    std::print("result: {}\n", *r);
}
```

## 九、展望 C++26（规划中）

- **Reflection（反射）**：编译期遍历类型成员，是 C++ 社区期盼多年的"杀手锏"特性。
- **Contracts（契约）**：前置/后置条件与断言（`pre`/`post`/`expects`），防御式编程进标准。
- **模式匹配**：对标 Rust 的 `match` 表达式。

## 十一、编译器支持与标准指定

### 主流编译器支持现状

| 标准 | GCC | Clang | MSVC（VS） |
| ---- | --- | ----- | ---------- |
| C++11 | ✅ 4.8+ | ✅ 3.3+ | ✅ VS2015+ |
| C++14 | ✅ 5+ | ✅ 3.4+ | ✅ VS2015+ |
| C++17 | ✅ 7+ | ✅ 5+ | ✅ VS2017 15.7+ |
| C++20 | ✅ 11+（较完整） | ✅ 14+（较完整） | ✅ VS2019 16.10+（较完整） |
| C++23 | ✅ 12+（部分） | ✅ 17+（部分） | ✅ VS2022 17.8+（部分） |

### 编译时如何指定版本

```bash
# GCC / Clang（Linux / macOS）
g++ -std=c++17 main.cpp -o main
g++ -std=c++20 main.cpp -o main
clang++ -std=c++2b main.cpp -o main   # 部分编译器用 2b/2c 表示未定稿的新标准

# MSVC（Visual Studio）
# 项目属性 → C/C++ → 语言 → C++ 语言标准 → 选择 ISO C++17 / C++20 / C++23
# 或命令行 /std:c++17 /std:c++20
```

### 快速判断代码用了哪个标准

- 见到 `nullptr`、lambda、智能指针、范围 for → 至少 C++11
- 见到 `if constexpr`、结构化绑定、`optional` → C++17
- 见到 `concept`、`co_await`、`<=>`、`import` → C++20

## 十二、怎么选版本

| 场景 | 建议 |
| ---- | ---- |
| 初学者入门 | 直接从 **C++11 语法**学起，目标 C++17，避开老式指针风格 |
| 校招/面试 | 默认 **C++17**，C++20 的 concept/协程作加分项 |
| 工业项目 | 至少 C++17；新项目尽量上 C++20 |
| 读开源/老代码 | 先识别项目标准（看 CMake 的 `CMAKE_CXX_STANDARD`）再决定写法 |
| 底层/嵌入式 | 受编译器版本限制，可能停留在 C++11/14，写法需保守 |

> 💡 一句话结论：**C++11 是门槛，C++17 是主流，C++20 是趋势，C++23 是前沿。**
