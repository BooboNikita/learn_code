# OpenGL 入门

既然你已经对图形编程至少有了初步认识，下面有必要讨论一下如何在你自己的项目中开始使用 OpenGL。本节讨论假定你已经知道如何在你选择的构建系统中搭建一个构建工程。

最省事的办法是直接使用[非官方 OpenGL SDK](http://glsdk.sourceforge.net/docs/html/index.html)。它是一套文档完善的工具集合，用来编写简单的 OpenGL 应用。它提供了编译着色器的函数、我们之前用过的基于鼠标的控制、图像加载工具，以及其他各种编写 OpenGL 应用必不可少的辅助工具。具体使用方法见该 SDK 的网站。

## 手动使用

如果你选择不使用该 SDK，那么就得自己动手搭建一套有用的工具。

要使用 OpenGL，你需要做两件事：创建一个窗口并在其上附加一个 OpenGL 上下文，以及为该上下文加载 OpenGL 函数。你可能还需要其他一些工具（向量数学、模型加载、图像加载等），但前面这两项是必须的，除非你打算手写实现。

### 窗口与 OpenGL 创建

窗口（即 GUI 操作系统环境中可显示的表面）非常依赖具体平台。大多数 Linux 发行版依赖 X11 完成最底层的窗口创建，而 X11 提供了称为 GLX 函数的钩子，用于把 OpenGL 附加到这些窗口上。在 Windows 上则使用 Win32 API 创建窗口，并用 WGL API 把 OpenGL 附加到这些窗口。

由于窗口创建和 OpenGL 附加都依赖具体平台，市面上出现了若干跨平台工具，让你能够编写与平台无关的 OpenGL 代码。这些教程使用的工具是 FreeGLUT，它作为 SDK 的一部分包含在源码发行包中。可选的工具还有不少，下面我们会介绍其中许多。

**FreeGLUT**

FreeGLUT 基于最初的 GLUT（OpenGL 实用工具包）。你绝不该使用 GLUT；它已经很老，十年都没有更新了。不过 FreeGLUT 与它 100% 向后兼容：任何使用 GLUT 的应用都可以改用 FreeGLUT，无需改动任何源码。

FreeGLUT 为应用创建并管理窗口。它提供回调函数，让用户能够响应各种事件。在这些教程中，框架负责初始化 FreeGLUT 并注册若干标准回调，每个教程自行实现这些回调。当显示内容需要更新、用户改变窗口大小、用户按下按键或发生鼠标输入时，都会调用相应的回调。

FreeGLUT 既能创建窗口，也能创建全屏显示。它还提供有限的菜单支持：虽然不能让你创建菜单栏，但可以创建右键上下文菜单。

FreeGLUT 适合快速搭建某个效果的原型。但用它来构建真正的应用会有问题，尤其是在你有特定计时需求的时候。消息处理循环归 FreeGLUT 所有，这限制了你在严格计时等方面所能采用的做法。FreeGLUT 适合演示程序和原型开发，但正式应用应当避开它。

FreeGLUT 确实提供了一些文本渲染函数，但在使用基于着色器的渲染时它们无法工作。如果你使用的是核心 OpenGL 上下文，这些函数会失败；在兼容性上下文中，如果上下文上绑定了 program object，它们同样会失败。

FreeGLUT 使用 X-Consortium 许可证。

**GLFW**

GLFW 是 FreeGLUT 的另一个选择。和 FreeGLUT 一样，GLFW 也相当精简，它提供了创建窗口或全屏显示的手段。

两者最大的区别在于：FreeGLUT 拥有消息处理循环，而 GLFW 没有。GLFW 要求用户主动轮询它以处理消息，这使用户能够为渲染维持相当严格的时序。代价是 GLFW 程序比 FreeGLUT 程序稍微复杂一些（这也是这些教程选择 FreeGLUT 的原因），但这也意味着 GLFW 在正式应用中更为有用。

此外，GLFW 在若干方面提供了更稳健的支持。FreeGLUT 和 GLFW 都能创建全屏应用，但 GLFW 提供了查询可用分辨率的手段。两者都提供时间查询，但 GLFW 的定时器分辨率高得多，而 FreeGLUT 的定时器只有毫秒级分辨率。两者都支持手柄输入，但 GLFW 还能查询手柄的基本信息（按键和轴的数量），并且支持任意数量的按键和轴。

总体而言，它比 FreeGLUT 更偏向游戏开发。GLFW 目前缺少的一项能力是创建 sRGB 默认帧缓冲。GLFW 使用 zLib 许可证。

**多媒体库**

多媒体库是以跨平台方式处理图形、声音、输入等事务的库。这一切都源自 DirectX——微软的一个库，它处理图形、声音、输入以及少量其他事务，目的是让游戏开发者的日子更好过些。DirectX 的宗旨是与硬件无关：代码可以针对任意图形或声音硬件来编写，由 DirectX 负责处理其中的细节。

跨平台多媒体库同样能做到这一点，而且它们把这些东西带到了跨平台的层面。它们通常支持三大操作系统（Windows、Linux、MacOSX），可能还会支持 BSD 或其他各色 UNIX。与 DirectX 不同，这些多媒体库并没有自建 3D 渲染系统，而只是提供了一条使用 OpenGL 的途径。

最大的两个多媒体库是 [SDL (Simple Directmedia Layer)](http://www.libsdl.org/) 和 [SFML (Simple and Fast Multimedia Library)](http://www.sfml-dev.org/)。SDL 出现较早，但仍在持续更新。它是一个 C 语言库，如果你对 C 风格的做法不感冒，或许该避开它。SDL 1.3 正在开发中，据说会支持移动平台。SDL 使用 zLib 许可证。

SFML 是较新的库，提供 C++ API。SDL 是一个大而全的库（在 Windows 上还需要 DirectX 之类的依赖），而 SFML 更像是一个按需挑选的包组。基础包只包含输入处理和创建窗口的能力，另有一些包在此基础上扩展。此外，SFML 让它的窗口可以与其他 GUI 工具包集成（见下文），这使得构建使用真正 GUI 控件的非游戏类应用更加容易。SFML 使用 zLib 许可证。

[Allegro](http://alleg.sourceforge.net/) 是一个面向游戏的多媒体库。第 5 版的图形子系统原生支持 OpenGL。它使用 C 接口，并提供若干高级 2D 渲染函数。Allegro 使用“giftware 许可证”，它与 MIT 许可证颇为相似。

**GUI 工具包**

有不少跨平台 GUI 库负责细致的窗口管理、提供各种控件，整体上就像一个功能完备的窗口系统。它们大多支持在其中一个或多个窗口中使用 OpenGL。Qt、wxWidgets、GTK 都提供了某种形式的 OpenGL 窗口供你使用。

具体使用哪种窗口创建工具完全由你决定；你可能的各种需求远超本书的讨论范围。

### 函数加载

OpenGL 上下文创建之后，还必须加载 OpenGL 的函数。在普通的库中，这其实不算一个步骤：那些函数会有一份供你包含的头文件，以及某种形式的库，你以静态或动态方式链接即可。但由于 OpenGL 周边存在各种复杂性，在大多数平台上它无法这样工作。

因此，用户必须向上下文本身查询要加载的函数。而 OpenGL 的函数非常多，所以通行的做法是用一个库来替你完成这件事。

**GL Load**

它随非官方 OpenGL SDK 一同提供。虽然 SDK 的大部分内容都不是为高性能场景准备的，但 GL Load 在这方面的表现完全够用。毕竟这通常只是一次性的初始化步骤，性能最终还是无关紧要的。

GL Load 对核心上下文和兼容性上下文的处理同样出色。事实上，与大多数 OpenGL 加载库不同，它不仅区分核心头文件与兼容性头文件，还按 OpenGL 版本区分头文件。因此如果你在 OpenGL 3.3 下工作，就不会看到更高版本的函数或枚举值（除非它们以 OpenGL 扩展的形式对外提供）。

GL Load 使用 MIT 许可证。

**GLEW**

GLEW（OpenGL Extension Wrangler）大概是使用最广泛的 OpenGL 加载库。虽然从定位上说它是为加载扩展函数而设计的，但用来加载 OpenGL 核心函数也同样好用。

GLEW 主要的缺点是它与核心上下文配合不好。虽然有一些实验性的支持试图让它工作起来，但那毕竟是实验性的。GLEW 使用 MIT 许可证。

**GL3W**

GL3W 的独特之处在于它严格来说并不是一个库。它是一个 Python 脚本，下载并解析一个头文件，再用这个头文件生成一个库。这让它能始终跟上它所下载的源文件。缺点在于这个源文件的格式可能变化，一旦变化，这个工具就会失效。

GL3W 专门面向核心上下文设计，无法配合兼容性上下文或较老的 OpenGL 版本使用。作为一个 Python 脚本，它需要 Python 环境，具体来说需要 Python 2.6；在更高版本的 Python 上能否工作尚不清楚。GL3W 是公有领域软件。

### 初始化

选好工具之后，下一步就是让它们真正工作起来。下载并编译之后，你需要把它们注册到你选择的 C/C++ 构建工具中。在 Linux 平台上，这类东西通常有一个全局注册表；而在 Windows 上，它们就放在你放的地方。

具体怎么用取决于你选的工具。不过 OpenGL 上下文创建工具的总体思路是：先用一系列命令把创建上下文所需的参数交给底层系统，然后调用一个函数，用这些参数创建上下文。只有在这个过程成功完成*之后*，才应该调用 OpenGL 函数加载系统所使用的初始化函数。你所用工具的文档里应该会说明这一点。

这两步都做完之后，你应该就能发起 OpenGL 调用了。至于如何交换帧缓冲（这不属于 OpenGL API 的一部分），具体做法同样要交给窗口管理工具。
